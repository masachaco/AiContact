# 草案: 大容量サンプル（アセット）

状態: **草案（未実装）**。合意後に `docs/ACI-SPEC.md` へ取り込み、実装する。

## 1. 目的

マルチサンプルのピアノやストリングスなど、**数 GB 規模のサンプル**を使う音源を扱えるようにする。

| 要件 | 内容 |
|---|---|
| 容量 | 1 音源あたり数 GB。将来はメモリに入りきらない量（ディスクストリーミング） |
| 音源と同じ扱い | サンプルも音源ファイルと同じく**指定された場所（絶対パス）を参照し、プロジェクトを開くたびに読む**。中央のライブラリや `~/.aicontact` は使わない |
| 失敗は失敗として伝える | 見つからない・読めない・**デプロイ後に書き換えられた**サンプルがあれば、そのスロットはエラー表示にして鳴らさない（代わりのもので鳴らしたり、一部だけで鳴らしたりしない） |
| サンドボックス | 音源（wasm）はファイルに触れない。読むのはホストで、渡すのは音源が宣言したサンプルだけ |
| 共有 | 同じサンプルファイルを複数のスロット・プラグインインスタンスで使ってもメモリ上は 1 つ |
| 将来性 | ディスクストリーミングへ移行しても音源のコードは書き換えない |

小さなサンプル（〜数十 MB）は、今まで通り wasm に埋め込んでもよい。

## 2. 全体像

```
 /Users/me/Music/Instruments/
   piano.aci.wasm     ← スロットが参照する音源ファイル（プロジェクトには絶対パスが保存される）
   piano.assets/      ← サンプル。音源ファイルの隣の「<名前>.assets/」フォルダ
     c4.wav
     c5.wav
        │ プロジェクトを開く / デプロイ
        ▼ ホストがバックグラウンドで読み込み・デコード
 共有キャッシュ（ネイティブメモリ。同じファイルは 1 つだけ）
        │ aci_asset_read()
        ▼
 音源の wasm メモリ（必要な範囲だけコピー）
```

- サンプルの場所は**音源ファイルの位置で決まる**: `<音源ファイル名から .aci.wasm を除いた名前>.assets/`。
  音源ファイルが絶対パスで参照されるので、サンプルも実質的に絶対パスで決まる
- 「音源 = `.wasm` とその隣の `.assets/` フォルダ」というまとまりで、移動・コピー・受け渡しはフォルダごと行う
- プロジェクトに保存されるのは、音源ファイルのパスとハッシュ、**各サンプルの SHA-256**、設定。サンプル本体は入らない
- 音源ファイルと同じく、デプロイした時点の中身だけを信頼する。外部から書き換えられたサンプルは読み込まずエラーにする
  （細工したファイルでデコーダの脆弱性を突かれたり、意図しない音にすり替えられたりしないように）。
  変更が自分のものなら、デプロイし直すと新しい中身を信頼する

## 3. 音源ファイル側

### 3.1 宣言（カスタムセクション `aci.assets`）

音源が使うサンプルの**名前の一覧**を、wasm のカスタムセクションに JSON で入れる。CLI がビルド時に
`<名前>.assets/` フォルダから自動生成するので、C のソースに一覧を書く必要はない。

```json
{ "assets": ["c4.wav", "c5.wav", "release/c4.wav"] }
```

- 名前は `.assets/` フォルダ内の相対パス（UI ファイルと同じ文字種の制限、`..` 不可）
- ホストは宣言されたファイルだけを読む。フォルダにある宣言外のファイルは無視する
- 1 音源あたりの数の上限は 4096 程度（要検討）

### 3.2 ホスト関数（インポート）

`env.aci_log` に加えて以下のインポートを許可する。すべて**オーディオスレッドから呼んでよい**
（ホストはロックもメモリ確保もしない）。

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `env.aci_asset_find` | `(name_ptr: i32, name_len: i32) -> i32` | 名前からアセット番号を返す。宣言に無ければ `-1`。`aci_init` で呼んで覚えておく想定 |
| `env.aci_asset_info` | `(asset: i32, info_ptr: i32) -> i32` | `info_ptr` に `{ i32 state; i32 channels; i32 frames; f32 sample_rate }` を書く。戻り値は `state`。`state`: `1` = 読み込み中、`2` = 使える、`-1` = 番号が不正 |
| `env.aci_asset_read` | `(asset: i32, channel: i32, frame: i32, count: i32, dst_ptr: i32) -> i32` | チャンネル `channel` の `frame` から `count` フレームを `f32` で `dst_ptr` に書く。戻り値は実際に書いたフレーム数（末尾では少なくなる）。読み込み中は `0` を返し、`dst` を無音で埋める |

- 返すデータは常に `f32`（-1〜+1）。ファイルの形式（16/24 bit など）はホストが吸収する
- サンプルレートの変換はしない。音源が `sample_rate` を見て再生速度を決める（サンプラーは元々ピッチを変えて再生するため）
- `count` の上限は 4096
- 見つからない・読めないサンプルがある場合、スロット自体がエラーになり音源は呼ばれない（4.3）。
  なので音源が「見つからない」状態を扱う必要はない
- ディスクストリーミングを入れた後も、このインターフェイスは変えない。データがまだ届いていなければ、その部分は
  無音になり、ホストがアンダーラン回数を記録する

### 3.3 SDK（`aci.h`）

```c
static int c4;                                   /* アセット番号 */
int aci_init(float sr, int max_frames) {
    c4 = aci_asset("c4.wav");                    /* aci_asset_find のラッパー */
    return 0;
}
void aci_process(int frames) {
    if (aci_asset_ready(c4)) {                   /* 読み込み中は無音などで待つ */
        float buf[256];
        int n = aci_asset_read(c4, 0, pos, frames, buf);
        ...
    }
}
```

補間付きの読み出し（ピッチ変更再生用）、ループ再生、ボイスごとの読み出し位置管理のヘルパーも用意する。

## 4. ホスト側

### 4.1 読み込み

- デプロイ時・プロジェクトを開いた時に、音源ファイルを読んだ後、宣言された各サンプルの存在を確かめる
- デプロイ時は各サンプルの SHA-256 を計算してスロットに記録する（プロジェクトに保存される）。プロジェクトを開いた時は、
  読み込んだ内容のハッシュを記録と照合し、**一致したものだけをデコードして音源に渡す**。照合は読み込みと同じ
  バックグラウンドスレッドで行う。今の自前の SHA-256 は約 190 MB/秒（4 GB で約 20 秒）なので、アセットの実装時に
  CPU の SHA 命令・OS の暗号 API（BCrypt / CommonCrypto / OpenSSL、1〜2 GB/秒程度）を使うか、BLAKE3（SIMD で数 GB/秒）に
  替える。再生（オーディオスレッド）には影響しない
- サンプルは**バックグラウンドスレッド**で読み込み・デコードし、プロセス全体で共有するキャッシュに入れる
  （キーは絶対パス＋更新日時＋サイズ、参照カウント付き）。音源のインスタンスは待たずにすぐ作るので、DAW は止まらない
- 読み込み完了は `state` が `2` になることで音源に伝わる（原子的に公開。オーディオスレッドはロックしない）
- どのスロットからも参照されなくなったサンプルはキャッシュから解放する
- メモリ上の形式はホストの自由（16 bit のファイルは 16 bit のまま保持し、読み出し時に `f32` へ変換する、など）
- ファイルを監視して読み直すことはしない（音源ファイルと同じ）。読み直したいときはデプロイし直す

### 4.2 対応形式

- v0: WAV（PCM 16 / 24 / 32 bit 整数、32 bit 浮動小数点、モノラル〜8 チャンネル）
- 次: FLAC（容量がおよそ半分になる。パブリックドメインの単一ヘッダデコーダ `dr_flac` を想定）

### 4.3 見つからない・読めない場合

- 存在確認の段階で見つからないものがあれば、スロットを `status: "error"` にし、見つからないファイルのパスを
  API・プラグイン画面・ログに出す。音源は鳴らさない
- ハッシュが記録と一致しないもの（記録が無いものを含む）も同じくエラーにし、書き換えられたファイルを示す
- バックグラウンドのデコードで失敗した場合（壊れたファイル、非対応形式）も、同じくスロットをエラーにする
- 直し方は音源ファイルと同じ: ファイルを正しい場所に戻してデプロイし直すか、プラグイン画面の「Locate...」で
  音源ファイル（とその隣の `.assets/`）の場所を指定し直す

### 4.4 セキュリティ

- デプロイ後に書き換えられたファイルは、デコードする前に（ハッシュの照合で）弾く
- ホストが読むのは、**スロットの音源ファイルの隣の `<名前>.assets/` 内にある、宣言された名前のファイルだけ**。
  名前は相対パスの制限（`..` 不可、文字種）を満たすものに限り、通常のファイルだけを開く
- 音源が読めるのは自分で宣言したサンプルだけ

### 4.5 ストリーミング（将来）

メモリに入りきらないライブラリ向けに、各サンプルの先頭だけをメモリに置き、残りはディスクから先読みする方式に拡張する。
読み出し位置の先読みはホストのバックグラウンドスレッドが行う。音源から見たインターフェイス（3.2）は変わらない。

## 5. API・CLI

### 5.1 API

- 新しいメソッドは不要。`slot.deploy` は今まで通り音源ファイルのパスを受け取り、隣の `.assets/` も読む
- スロット情報に `assets: {total, loaded, bytes}` と、読み込み中・失敗の情報を追加する。
  `status` は読み込み中 `"loading"`、失敗 `"error"`
- ファイルはラックのマシン上に置く（WSL から Windows のラックを操作する場合は、CLI が `\\wsl.localhost\...`
  形式に変換するので WSL 内に置いたままでよい）

### 5.2 CLI

- `build` / `deploy`: ソースの隣の `<名前>.assets/` を見て `aci.assets`（名前の一覧）を埋め込む。
  ビルド結果の `<名前>.aci.wasm` と `.assets/` が同じフォルダに並ぶ
- `deploy`: 読み込み完了（または失敗）まで待ってから結果を返すオプション（`--wait`）

## 6. 検証（validate）

- サンプルが揃っていれば、それを使って試奏レンダリングする。揃っていなければエラーとして報告する
- 宣言されていない名前を `aci_asset_find` した場合は警告（綴り間違いの検出）

## 7. 決めること

1. フォルダ名の規則（`<名前>.assets/` でよいか）
2. FLAC を最初から入れるか
3. 1 プロセスのサンプル用メモリの上限と、超えたときの扱い（エラーにする／ストリーミングを待つ）
4. 読み込み中のスロットの扱い（今の案: 鳴らせる状態になるまで音源の `aci_asset_info` が「読み込み中」を返す。
   スロットの状態は `"loading"` として画面に出す）
